# Replace qjackctl with jack-graph

## Overview

Replace the custom qjackctl build and all associated D-Bus integration infrastructure with the simpler `jack-graph` application. jack-graph is a prebuilt binary that provides a visual graph interface for JACK/ALSA port connections without the complexity of D-Bus service control.

**Key principle**: Remove qjackctl-specific code while preserving all other jack-bridge functionality (Bluetooth, mxeq, recording, device switching, headless JACK startup).

---

## Scope

### What gets removed
- Custom qjackctl binary installation
- qjackctl desktop files and autostart entries
- qjackctl icons (SVG and PNG files)
- qjackctl D-Bus configuration helpers (jack-bridge-qjackctl-setup, jack-bridge-verify-qjackctl)
- jack-bridge-dbus D-Bus service binary and init script
- D-Bus service activation files (org.jackaudio.service.service, org.jackaudio.service.conf)
- Polkit rules specific to qjackctl (50-jack-bridge.rules)
- qjackctl user configuration seeding (~/.config/rncbc.org/QjackCtl.conf)
- build-qjackctl.sh script
- Makefile dbus target and related source references
- All qjackctl documentation references in README.md

### What gets added
- jack-graph binary installation from contrib/bin/
- jack-graph desktop file (from jack-graph/resources/jack-graph.desktop)
- No autostart entry (user launches jack-graph manually when needed)

### What stays unchanged
- All Bluetooth functionality (bluealsad, bluealsa binaries, ALSA plugins, bluetoothd init script)
- mxeq binary and desktop integration
- Recording functionality in mxeq
- Device switching (internal/USB/HDMI/Bluetooth)
- jackd-rt init script (headless JACK startup)
- jack-bridge-ports init script
- jack-connection-manager init script and binary
- jack-bridge-bluetooth-config init script
- 50-jack.conf (critical ALSA-to-JACK bridge)
- All ALSA configuration files
- All group membership logic (audio, bluetooth groups)
- PulseAudio autospawn disable
- Realtime limits configuration
- All user config seeding for jack-bridge devices.conf

## Notes

- jack-graph does NOT need D-Bus integration - it connects directly to JACK via the JACK C API
- jack-graph does NOT start JACK - it assumes JACK is already running (via jackd-rt init script)
- jack-graph does NOT autostart - users launch it manually when they need to see/connect ports
- The jack-bridge-dbus binary source files don't exist in src/ anyway, so removing the Makefile dbus target is safe
- All Bluetooth functionality is independent of qjackctl and D-Bus service control
